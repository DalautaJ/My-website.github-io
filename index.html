Who Are Hackers?

"Hacker" simply means someone who breaks into computer systems. What matters is permission and intent. Hackers are grouped by "hat" colors.

🎩

White Hat

Ethical hackers hired to find weaknesses legally, then help fix them. Also called penetration testers.

Legal • Permission • Protects
🖤

Black Hat

Criminals who break in to steal data, money or cause damage.

Illegal • Malicious • Profit
🩶

Grey Hat

Hack without permission but not to cause harm, often reporting the hole afterward. Still illegal.

No permission • Mixed intent
👶

Script Kiddie

Beginners who run other people's ready-made tools without understanding them. Still dangerous.

✊

Hacktivist

Attack sites to push a political or social message, such as defacing pages or leaking data.

🏛️

State-Sponsored (APT)

Well-funded, patient groups backed by governments, usually after secrets or infrastructure.

🔵

Blue Team

The defenders: monitor, patch and respond to incidents every day.

🔴

Red Team

Authorized "attackers" who test the blue team's defenses so weaknesses get fixed first.

Anatomy of an Attack

Most attacks follow similar stages. Understanding them shows you where to stop the attacker, and every stage has a defense.

  1. Reconnaissance

    The attacker gathers public information: company websites, employee names on social media, exposed server details.

    Defense: share less publicly, hide version banners, train staff on oversharing.

  2. Scanning

    Automated tools look for open ports, running services and known vulnerabilities.

    Defense: close unused ports, keep software patched, use an intrusion detection system.

  3. Gaining Access

    Entry happens through weak or stolen passwords, phishing, or an unpatched flaw.

    Defense: MFA, strong passwords, fast patching, email filtering.

  4. Maintaining Access

    Once inside, attackers try to stay hidden by creating hidden accounts or backdoors and moving to other machines.

    Defense: monitor accounts, file integrity checks, network segmentation.

  5. Covering Tracks

    They try to erase or alter logs so nobody notices the break-in.

    Defense: send logs to a separate, protected log server so they can't be wiped.

Malware Types

Malicious software comes in many forms. Knowing the differences helps you recognize and respond.

🦠

Virus

Attaches to a file and spreads when that file is opened or shared.

🪱

Worm

Spreads by itself across networks without needing a user to click anything.

🐴

Trojan

Pretends to be useful software while secretly doing harm or opening a backdoor.

📹

Spyware & Keyloggers

Silently record activity and keystrokes to steal passwords and data.

🤖

Botnet

Many infected machines controlled remotely, often used for DDoS attacks.

⛏️

Cryptojacking

Secretly uses your server's power to mine cryptocurrency, slowing it down.

Know Your Enemy

A data server stores valuable information, so attackers constantly probe it. These are the most common attacks, each paired with its best defense.

🎣

Phishing

Fake emails or sites trick people into giving away passwords or running malware.

Defense: staff training, MFA, email filtering.
🔑

Brute Force

Bots try thousands of passwords per minute until one works.

Defense: rate limiting, lockouts, long passwords, MFA.
💉

SQL Injection

Malicious input is slipped into a database query to read or change data.

Defense: parameterized queries and input validation.
🌊

DDoS

A flood of traffic from many machines knocks the server offline.

Defense: CDN, traffic filtering, auto-scaling.
🔒

Ransomware

Malware encrypts your files and demands payment to unlock them.

Defense: offline backups, patching, least privilege.
🕳️

Unpatched Software

Attackers scan for servers running old software with known holes.

Defense: regular updates and vulnerability scans.
🕵️

Insider Threats

A careless or malicious employee with too much access causes a breach.

Defense: least privilege, audit logs, access reviews.
👂

Man-in-the-Middle

Someone secretly intercepts traffic between users and the server.

Defense: HTTPS/TLS everywhere, VPN, HSTS.

Defense in Depth

No single tool is enough. Layer your protections so that if one fails, the next one still stands.

  1. Firewall & Network Segmentation

    Allow only the ports you need (for example 443 for HTTPS) and block everything else. Keep the database on a private network that the internet can't reach.

  2. Patch & Update Everything

    Enable automatic security updates for the OS, web server, database and libraries. Most breaches use holes that already have a fix.

  3. Strong Authentication + MFA

    Use long unique passwords with a password manager, add multi-factor authentication, and prefer SSH keys over passwords. Disable direct root login.

  4. Encrypt Data Everywhere

    Use TLS for data in transit and disk or database encryption for data at rest. Store user passwords only as salted hashes (bcrypt or Argon2).

  5. Least Privilege

    Give every user and program only the access it needs. A web app shouldn't connect to the database as an admin.

  6. Monitor & Log

    Collect logs, alert on strange behavior (many failed logins, odd hours, big downloads), and use tools like fail2ban or an IDS/IPS.

  7. Backups (3-2-1 Rule)

    Keep 3 copies of your data, on 2 different media, with 1 stored offsite or offline. Test restores regularly, because a backup you can't restore is useless.

  8. Secure Configuration

    Remove default accounts and sample files, hide version banners, and run regular vulnerability scans and penetration tests on systems you own.

If You Get Attacked

Even good defenses can fail. Have a plan, and follow these four stages calmly.

🚨

1. Detect

Confirm the alert is real. Record the time, affected systems and any suspicious activity.

🧯

2. Contain

Isolate affected machines from the network and disable compromised accounts. Don't wipe evidence yet.

🧹

3. Eradicate

Find the root cause, remove malware or backdoors, and patch the hole that let them in.

♻️

4. Recover

Restore from clean backups, change all passwords and keys, monitor closely, then write up lessons learned.
